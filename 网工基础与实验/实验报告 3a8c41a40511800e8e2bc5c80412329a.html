🤩stub 末梢区域

需求：使该拓扑图的area 1即使在外部路由产生问题或者动荡时也不受影响。

区域里允许存在 1/2 /3 类LSA ，不允许存在 4/5 类LSA ，意思是引入的外部路由如果动荡，不会影响本区域，想访问外部路由，在ABR 产生一条  3类 的默认路由功能的 LSA

  stub

😜totally  STUB完全末梢区

需求：既不想外部路由影响也不想其他区域影响。

区域里允许存在 1、2类 LSA , 不允许存在 3/4/5 LSA  ，意思是引入的外部路由动荡不会影响本区域，同时其他的LSA 动荡也不会影响本区域， 想访问其他区域及外网 ， ABR 上产生一条 3类的 默认路由功能的 LSA  （即上面产生的默认路由）

配置命令

在区域1 内所有设备配置完STUB 之后， 在 ABR 区域上追加下面的命令
 area 0.0.0.1 
  stub no-summary

🤪NSSA

需求：实现合作伙伴通过公司网络访问数据中心（AR1的GE0/0/0接口地址删掉以及其OSPF的宣告也删除）。

但是现状是，既不能有外部路由也能有其它区域的路由，既3、4、5类的LSA都被禁止了

于是出现了NSSA

这个区域里不存在5类LSA  ， 但是可以存在外部路由，这个外部路由不是以5类LSA 形式存在的， 以 7类LSA 形式存在。

区域里允许存在 1、2、3、7类 LSA , 不允许存在 4/5 LSA  ，意思是引入的外部路由动荡不会影响本区域， 想访问其他区域及服务器外网 ， ABR 上产生一条 7类的 默认路由功能的 LSA  ，这条LSA 具有将特殊区域的7类LSA 转换成其他区域认识的5类LSA 。 在ASBR 上产生去往合作伙伴的7类LSA  。

配置命令：

ospf 1 
 area 0.0.0.1 
  nssa
所有区域1内的设备都配置NSSA，删除stub

🤩totally NSSA

为了同时外部路由和其他区域的路由不会影响到本区域，即

区域里允许存在 1、2 . 7类 LSA , 不允许存在 3/4/5 LSA  ，意思是引入的外部路由动荡不会影响本区域，相访问其他区域及服务器外网 ， ABR 上产生一条3类 默认路由 ，也会产生一条7类默认路由，这个七类是为了进行7转5类 。 ASBR 上产生七类LSA 是为了访问合作伙伴的网络。

☺️静默接口

接口参与OSPF路由计算，但是不发送、不接收OSPF报文。（比如用在主机和路由器之间）

这样就阻断LSA的报文向主机进行发送这种浪费资源的行为

[AR1-ospf-1]silent-interface ?
  Cellular         Cellular interface
  GigabitEthernet  GigabitEthernet interface
  all              Suppress and receive routing on all interfaces

对于第一种在区域里用network宣告的解决办法：abr路由汇总

配置命令：

[AR2-ospf-1-area-0.0.0.12]abr-summary ?
  IP_ADDR<X.X.X.X>  IP address
  
  
  需要在该域的ABR设备上配置
  这里问号处应填写该连续地址的相同前缀，可精细可大概
  例如：abr-summary 10.10.0.0 255.255.0.0
这里只精细到前面16位实际上可以继续展开。

第二种作为外部路由import-route引入的情况下，解决办法：asbr路由汇总

配置命令：

asbr-summary
在该外部路由的ASBR设备上配置
精细示例
asbr-summary 10.11.0.0 255.255.248.0

stub-router 用于将OSPF设备设置为 Stub Router（用在设备维护和启动保护的时候）。

作用：

降低本设备在OSPF中的路径优先级，让其他路由器尽量不选择经过该设备转发流量。

实现方式：

  • 修改自身发布的 Type 1 Router-LSA
  • 将Transit链路Cost设置为最大值 65535
  • 其他OSPF设备重新计算SPF后，会绕开该设备

详细查询命令步骤：

[AR6]route-policy ?
  STRING<1-40>  Name of the route policy

[AR6]route-policy lxf ?
  deny    Specify a deny rule
  permit  Specify a permit rule

[AR6]route-policy lxf permit ?
  node  Node of the route policy

[AR6]route-policy lxf permit node ?
  INTEGER<0-65535>  Index of the node

[AR6-route-policy]if-match ?
  acl                  Specify an ACL
  as-path-filter       BGP AS path list
  community-filter     Match BGP community filter
  cost                 Match metric of route
  extcommunity-filter  Match external community filter
  interface            Specify interface matching first hop of routes
  ip                   IP information
  ip-prefix            Specify address prefix-list
  ipv6                 IPv6 Information
  mpls-label           Give the Label
  rd-filter            Route-distinguisher filter
  route-type           Match route-type of route
  tag                  Match tag of route

[AR6-route-policy]if-match acl ?
  INTEGER<2000-2999>  Apply basic ACL
  STRING<1-32>        Specify ACL name

[AR6-ospf-1]import-route direct route-policy lxf ?
  cost  Set cost
  tag   Specify route tag
  type  Metric type of imported external routes

route-policy

  1. route-policy 本身不会生效，必须被调用，route-policy 只是一个规则，需要绑定到具体功能中
  1. route-policy 由 node 组成
  • lxf：策略名称
  • permit/deny：允许或拒绝
  • node 10：匹配节点编号

多个 node 按编号从小到大匹配。（步长为10）

  1. node 之间是“或”的关系
  1. 同一个 node 内多个 if-match 是“与”的关系
  1. ACL和route-policy使用时，默认规则是拒绝
route-policy lxf permit node 10
 if-match acl 2000
 if-match ip-prefix test
 
 必须同时满足：
ACL 2000
ip-prefix test

才匹配成功。

并且，逻辑接口和acl匹配要完全匹配，掩码也要一致。
