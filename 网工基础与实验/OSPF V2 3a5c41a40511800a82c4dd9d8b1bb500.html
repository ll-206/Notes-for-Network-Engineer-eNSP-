🧓🏼动态路由的分类

一、按路由算法分类

  1. 距离矢量路由协议（Distance Vector，DV）
    • 原理：每个路由器只知道到各目的网络的距离（跳数）和下一跳路由器，通过定期广播路由表进行更新。
    • 代表协议：
      • RIP（Routing Information Protocol）：替代静态路由，小型网络使用；有效网络直径为15跳
      • BGP（Border Gateway Protocol）：路径矢量，用于自治系统间路由
    • 特点：配置简单，收敛慢，容易出现环路，需要配合防环机制（Split Horizon、Hold-down 等）
  1. 链路状态路由协议（Link State，LS）
    • 原理：每个路由器了解整个网络拓扑，计算到各目的网络的最短路径（通常用 Dijkstra 算法）
    • 代表协议：
      • OSPF（Open Shortest Path First）：基于 IP；企业使用较多；
      • IS-IS（Intermediate System to Intermediate System）：基于 CLNP；数据中心较多使用；
    • 特点：收敛快，路由环路少，但配置复杂，占用更多内存和 CPU
  1. 混合型路由协议（Hybrid）
    • 结合距离矢量和链路状态特性
    • 代表协议：EIGRP（Enhanced IGRP）
    • 特点：收敛速度快，支持大规模网络，计算资源适中

二、按使用范围分类

  1. 内部网关协议（IGP, Interior Gateway Protocol）
    • 用于公司内部或自治系统内部
    • 常见协议：RIP、OSPF、EIGRP、IS-IS
  1. 外部网关协议（EGP, Exterior Gateway Protocol）
    • 用于公司之间或自治系统之间
    • 常见协议：BGP

😩距离矢量路由协议

典型协议：RIP，距离矢量协议 DV，使用跳数作为度量值；

数据包转发方向（Packet Forwarding）

  • 这是数据流实际走的路径。
  • 例如你图中从 R1 发往 10.0.3.3 的数据包：
    • 方向：R1 → R2 → R3 → 10.0.3.3
    • 每台路由器根据自己的路由表下一跳决定包的出接口

路由信息传播方向（Routing Update）

  • 这是路由器交换路由表信息的方向，用于学习下一跳。
  • 例如 DV 协议下：
    • R3 广播自己的路由表给 R2 → R2 学会“去 10.0.3.3 下一跳 R3”
    • R2 再广播给 R1 → R1 学会“去 10.0.3.3 下一跳 R2”
  • 方向是从目的网络发向邻居路由器，但它不是实际数据包路径，只是信息传播。

基本概念

距离矢量路由协议，英文是 Distance Vector Routing Protocol，DV。

它的核心思想是：

路由器不需要知道全网拓扑，只需要知道：

去某个目的网络，应该从哪个下一跳走，距离有多远。

也就是说，距离矢量路由协议关注两个东西：

内容含义
距离 Distance到目的网络的开销，比如跳数、Metric
矢量 Vector去目的网络的方向，也就是下一跳

运行 DV 协议的路由器一般不知道完整网络拓扑。

类似针对上面展示的图

它只知道类似下面的信息：

目的网络下一跳距离
10.0.3.3R22 跳

对于 R1 来说，它不一定知道后面还有 R3，也不一定知道完整路径是：

R1 → R2 → R3 → 10.0.3.3

它只知道：

去 10.0.3.3，下一跳交给 R2。

这就是 DV 协议的特点：

不看全图，只看下一跳方向。

实现的流程

1. R3 先知道目的地址

因为 10.0.3.3 在 R3 旁边，R3 可能是直连的。

所以 R3 的路由表里先有：

目的地址：10.0.3.3
下一跳：直连
距离：0 或 1

也就是说，R3 自己知道：

10.0.3.3 就在我旁边。

2. R3 把自己的路由表告诉 R2

距离矢量协议会周期性地把自己的路由表发给邻居。

所以 R3 会把信息告诉 R2：

我知道 10.0.3.3 在哪里。

R2 收到后，会理解为：

既然 R3 知道 10.0.3.3，
那我去 10.0.3.3 就可以走 R3。

于是 R2 加入路由表：

目的地址：10.0.3.3
下一跳：R3
距离：1 跳

3. R2 再把自己的路由表告诉 R1

R2 学到这条路由后，也会把自己的路由表告诉邻居 R1。

R2 对 R1 说：

我知道去 10.0.3.3 的路。

R1 收到后，会理解为：

既然 R2 知道 10.0.3.3，
那我去 10.0.3.3 就先走 R2。

于是 R1 加入路由表：

目的地址：10.0.3.3
下一跳：R2
距离：2 跳

弊端：
收敛速度慢，网络变化后，路由表更新需要一段时间

容易产生环路，因为路由器只相信邻居信息，可能互相误导

容易出现计数到无穷，故障路由可能被一跳一跳错误传播

不适合大型网络，网络规模越大，更新越慢，路由不稳定风险越高

路由信息不够精确，只知道下一跳和距离，不知道完整路径

周期性更新占用带宽，即使网络没变化，也可能定期发送路由表

特点：

只知道下一跳，路由器只知道去某个目的网络应该交给哪个邻居

不知道全网拓扑，不清楚完整网络结构，只依赖邻居告诉自己的路由表

周期性更新，定期把自己的路由表发给相邻路由器

配置简单，协议机制简单，适合小型网络

根据距离选路，常见度量值是跳数，例如 RIP 根据跳数选择路径

逐跳转发，每台路由器只负责把数据包交给下一跳

🙁链路状态路由协议

链路状态路由协议通告的是链路状态信息

和距离矢量路由协议不一样的是链路状态路由协议告诉邻居路由器的是：接口有哪些、接口是否正常、接口连接了什么、链路开销。

😒术语

LSA（Link State Advertisement），链路状态通告，用来描述路由器的链路状态。

LSDB（Link State DataBase），链路状态数据库，用来存储收到的 LSA。

SPF（Shortest Path First），最短路径优先算法。

SPF Tree最短路径树，每台路由器以自己为根计算出的最优路径树。

🤤流程

一、

建立相邻路由器之间的邻居关系

目的：

确认对方也运行相同的路由协议
确认双方可以正常通信
为后续交换 LSA 做准备

在 OSPF 中，这个过程通常通过 Hello 报文完成。

在 OSPF 或其他链路状态路由协议中，LSA 是描述单个路由器链路状态的报文。它是协议中信息传播的基本单位。

表格的主要内容：

信息类型描述
Router ID产生 LSA 的路由器 ID
接口列表路由器上所有接口及其状态（up/down）
链路连接信息接口连接的邻居路由器或网络地址
链路开销每条链路的代价，用于 SPF 算法计算
类型字段LSA 类型（Router LSA, Network LSA, Summary LSA 等）
序列号 & 校验用于识别新旧 LSA、防止泛洪重复
  • 只描述链路状态，不直接告诉下一跳或路由表。
  • 在网络中通过邻居泛洪传播。
  • 每个路由器都会生成自己的 LSA。

二、

邻居之间交互链路状态信息和同步LSDB（Link State DataBase，链路状态数据库）。

邻居建立完成后，路由器之间开始交换 LSA，这些 LSA 最终都会被存入该域的每台路由器自己的 LSDB 中。

LSDB 是每台路由器用来存储整个 OSPF 区域内收到的所有 LSA 的数据库。经过同步后，一个路由器会拥有在同一个区域内每台路由器的链路状态信息，即在同一区域内，每台路由器的LSDB应该一致。它是路由器对网络拓扑的完整认知。

LSDB内容：

信息类型描述
所有 LSA包含所有邻居转发的 LSA，记录全网拓扑
LSA 来源每条 LSA 的产生者 Router ID、泛洪路径
LSA 类型标明每条 LSA的作用（Router LSA / Network LSA / Summary LSA / ASBR LSA）
状态信息接口状态、链路开销、连接对象等
版本 & 序列号用于判断是否是新 LSA

特点：

  • 全网拓扑存储：虽然路由器只能直接收到邻居 LSA，但通过泛洪，LSDB 最终包含整个区域的拓扑信息。
  • 统一性：同一区域内 LSDB 理论上在各路由器中一致。
  • 基础数据源：SPF 算法的输入就是 LSDB。

路由器如何知道全网链路状态？

本质上只能直接接收邻居路由器的报文，但是邻居路由器会转发其他路由器和它自己本身的LSA，通过泛洪，最终即使不相连也能获得全网链路状态。

注意：LSA的发送者不等于产生者，LSA字段标明产生者的Router ID，路由器收到 LSA 后根据产生者判断内容来源，而不是只看谁发送

如上图

  • R3 生成 LSA
    • 描述 R3 的接口状态、连接的邻居和链路开销
    • 不包含 LSDB 中的其他路由器 LSA 内容
  • R3 发送 LSA 给邻居 R2 和 R4
    • 一条 LSA 一条条发送，不是把 LSDB 打包发给邻居
  • R2 接收 R3 的 LSA
    • 检查序列号判断是否为新 LSA
    • 存入自己的 LSDB
    • 解析 LSDB → 更新自己对全网拓扑的理解
    • 继续泛洪给 R2 的其他邻居（如 R1）
  • R1 接收 R3 的 LSA
    • 同样存入 LSDB
    • 更新拓扑认知
  • R2 的 LSA 生成与泛洪
    • R2 生成的 LSA 只描述自己链路状态
    • 不会把 LSDB 中收到的 R3 或 R4 的 LSA 内容放进去
    • 再发送给 R1、R3、R4

三、

使用 SPF 算法计算最优路径

SPF 算法会计算出一棵以自己为根的、无环的、到达各个目的网络开销最小的树。每台路由器都根据相同的 LSDB，站在自己的角度计算最优路径。

四、

生成路由表，根据最短路径树生成路由表项加载到路由表。

SPF 算法计算完成后，路由器会把最优路径结果加载到自己的路由表中。

最终路由器不会把整棵 SPF 树都直接拿来转发数据，而是从 SPF 结果中提取出：

目的网段
下一跳
出接口
开销

然后形成路由表项。

OSPF

QSPF是IETF定义的一种基于链路状态的内部网关路由协议。目前针对IPv4协议使用的是OSPF
Version 2(RFC2328);针对IPv6协议使用OSPF Version 3(RFC2740)。

OSPF有以下优点:

基于SPF算法,以“累计链路开销”作为选路参考值

采用组播形式收发部分协议报文

支持区域划分

支持对等价路由进行负载分担

支持报文认证

协议号：89

🤤应用场景

OSPF 常用于中大型企业网络、园区网、校园网、数据中心内部网络等。

😠Router ID

注意：

Router ID 看起来像 IP 地址，但它不一定是真正用于通信的接口 IP。

OSPF 通过 Router ID 区分不同路由器，而不是只靠接口 IP 地址。

Router ID 的选择顺序如下：

优先级选择方式
1手动配置的 Router ID
2Loopback 接口中最大的 IP 地址
3物理接口中最大的 IP 地址

Loopback简介

Loopback，中文常叫“环回接口”或“回环接口”。

不是一根真实的网线接口，而是设备内部虚拟出来的一个接口。

不依赖物理接口、网线，只要设备正常运行该Loopback 接口通常就是 UP 状态。。

特点：

  • 作为稳定接口；如果用某个物理接口代表路由器，一旦该接口down，地址不可用，配置Loopback的话只要设备正常运行就能代表这个路由器。
  • 常用作RID，不受链路状态影响。不需要网线。
  • 可用作测试到达该路由器的连通性。
  • 配置示例（华为）：
system-view
interface LoopBack 0
 ip address 1.1.1.1 32
  • 备注：
    • 32 掩码表示单主机地址
    • 常用作 OSPF Router ID，稳定且不会随链路 Down 而消失

🤏🏼OSPF 区域 Area

Area 是 OSPF 网络中的一个逻辑分组。

把大量路由器划分到不同区域，可以减少每台路由器需要维护的 LSDB 规模，从而提高网络稳定性和收敛效率。

Area ID

OSPF 的区域编号叫 Area ID，也是 32 bit 的数值。

Area ID 可以写成十进制，也可以写成类似 IP 地址的格式。

  • 32 bit 限制：Area ID 是一个 32 位的二进制数。
    • 最大数值范围：0~4294967295（十进制）
    • 因为 OSPF 内部使用 32 位二进制存储，每个区域都必须在这个范围内。
  • 格式：
    • 十进制格式：直接写成一个整数，例如 0、1、65535、4294967295
    • IP 地址格式：写成类似 x.x.x.x，每个段 0~255，例如 0.0.0.0、0.0.0.1
    • 本质：两种格式只是显示不同，内部都转成 32 位二进制存储。
  • 互相转化：
    • IP 地址格式可以直接换成十进制：
      Area ID = 0.0.0.1  → 十进制 = 1
Area ID = 0.0.1.0  → 十进制 = 256
Area ID = 1.0.0.0  → 十进制 = 16777216
    • 反过来也可以把十进制数转成 IP 格式显示。
  • 总结：
    • 两种写法只是表示方式不同
    • 内部都是 32 bit 数字
    • 配置时根据习惯或可读性选择写法

😴OSPF 度量值 Cost

OSPF 使用 Cost 作为路径开销，也就是 OSPF 判断最优路径的依据。

Cost 越小，路径越优先。

OSPF 不直接看“跳数”，而是看路径总 Cost。

Cost=接口带宽参考带宽​

常见默认参考带宽：

100Mbit/s

所以：

Cost=接口带宽100Mbit/s​

🥲Loopback和LSA的关系

Loopback 是一个虚拟接口，不依赖物理链路，通常一直处于 UP 状态。

它在 OSPF 中最常见的作用是作为 Router ID（RID） 的候选地址。

RID 是 OSPF 路由器的身份标识，用来区分不同路由器，参与邻居关系建立、LSA 标识、DR/BDR 选举等过程。

Loopback 的重点不是发布链路信息
而是提供一个稳定的 RID

一台路由器会生成自己的 Router-LSA，
在这个 Router-LSA 里面描述自己所有参与 OSPF 的接口/链路信息。

area 0

Area 0 也叫骨干区域。

区域的作用：

1. 限制 LSA 泛洪范围(如果区域过大，计算会消耗大量CPU资源)
2. 减少 LSDB 大小
3. 减少 SPF 计算压力
4. 方便大型网络分层管理，防止环路
骨干区域（Area 0）：核心中转枢纽。
非骨干区域（Area 1, 2, ...）：必须与 Area 0 直接相连。
这种星型拓扑（Hub-and-Spoke）结构从逻辑上规定了所有跨区域流量必须经过 Area 0，从而有效地防止了区域间产生环路。

OSPF采用组播发送hello报文，直接发给这个区域所有配置了OSPF的设备
组播的作用是：把报文只发送给加入同一组播组的目标设备，实现“一次发送、特定设备接收”，避免广播打扰无关设备，也避免单播逐个发送。

在 ExStart 状态下，DD 报文主要用于协商主从关系和确定 DD 序列号，通常不携带 LSDB 中的 LSA 摘要信息；真正携带 LSA 头部摘要并进行数据库描述交换，是在 Exchange 状态。

Router ID 大的一方成为 Master
Router ID 小的一方成为 Slave

Master：控制 DD 报文序列号
Slave：跟随 Master 的序列号进行确认和响应

例如图中，在Exchange中当master的发出seq为Y时，slave则发出对应的seq为Y的回应DD

并且这种主从关系只在DD 报文交换阶段起控制作用

1. DD 报文：
   双方先互相展示自己有哪些 LSA 摘要

2. LSR 报文：
   发现自己缺少某些 LSA，就向邻居请求

3. LSU 报文：
   邻居把完整的 LSA 发过来
   LSA 是内容，LSU 是装 LSA 的报文

4. LSAck 报文：
   收到 LSA 后，发送确认

DR和BDR

出现的原因

MA网络（Multi-Access Network，多路访问网络）是指：

一个网络中，有多个设备可以同时接入，并且这些设备之间可以直接通信的网络。

在 OSPF 中，MA网络主要指 广播型多路访问网络（Broadcast Multi-Access），例如以太网。

但是重复的邻居构建和LSA泛洪会导致资源浪费，导致邻接关系多难以管理。

解决办法

选举DR（指定路由器）

DR：

· DR(Designated Router,指定路由器)负责在MA网络建立和维护邻接关系并负责LSA的同步。

· DR与其他所有路由器形成邻接关系并交换链路状态信息,其他路由器之间不直接交换链路状态信息。

· 为了规避单点故障风险,通过选举BDR(Backup DesignatedRouter,备份指定路由器),在DR失效时快速接管DR的工作。

😢选举过程

DR/BDR的选举是非抢占式的，具有稳定性（即使后面来的接口的优先级更高也不能够替换当前的DR/BDR）
DR/BDR的选举是基于接口的。（OSPF选DR和BDR时，比较的是参与该网络的接口，不是比较整台路由器。）
1）接口的DR优先级越大越优先。
2）接口的DR优先级相等时，Router ID越大越优先。
默认以太网链路 ，优先级值 1 
优先级值 0 ，表示 不参与选举
如果现网已经选举出DR /BDR ，新接入设备 优先级高于 当前DR ，也不能进行抢占成为DR

😆OSPF网络类型

OSPF会根据接口使用的二层协议，自动决定OSPF网络类型。
接口类型默认OSPF网络类型
Ethernet（以太网）Broadcast
PPP串口P2P
HDLC串口P2P

由于只看接口类型来判断网络类型，Ethernet一条链路的时候也会选举DR和BDR（主要用在多路访问的网络类型、广播型网络、NBMA非广播型网络），实际上浪费资源，反而用P2P会调高效率。

修改类型：

ospf network{p2p| p2mp| broadcast | nbma} 接口视图配置

网络类型常见链路DR/BDR广播/组播Hello时间Dead时间
Broadcast以太网（默认）需要支持10s40s
NBMA帧中继 FR需要不支持，需要手动指定邻居30s120s
P2PPPP、HDLC不需要支持10s40s
P2MP由其他类型转换而来，相当于多个P2P不需要支持30s120s

😉影响邻居关系的因素

1）两端地址是否互通（同一个网段）

2）两端设备是存在流量过滤  /策略（高级ACL）

[R2]acl 3000    // 在R2 上用ACL 过滤来自R1的OSPF报文流量
[R2-acl-adv-3000]rule 5 deny ospf source 192.168.12.1 0 destination 224.0.0.5 0
[R2-acl-adv-3000]quit
[R2]int g0/0/0   // 在 R2 连接R1 的接口的入方向 调用
[R2-GigabitEthernet0/0/0]traffic-filter inbound acl 3000
注意：  因为 ACL 和 流量过滤工具结合使用， 默认规则是允许，所以 ACL 要拒绝

阻拦了R1来到R2的流量，切断了邻居关系。

4）OSPF 两端接口网络类型不一致（Broadcast / P2P）

AR1                 AR2
Broadcast   ----    P2P

不一定导致 OSPF 邻居失败。

只要以下参数一致：

Area ID、Hello 时间、Dead 时间、认证信息、Router ID 不冲突

邻居状态也能达到FULL（邻居关系正常建立）

但是

——网络类型不一致会影响 DR/BDR 选举。Broadcast 网络需要进行 DR/BDR 选举，而 P2P 网络不进行 DR/BDR 选举，因此一端认为需要选举 DR/BDR，另一端认为不存在 DR/BDR，会造成 OSPF 逻辑不一致。

——虽然网络类型不一致时邻居可能保持 Full，但两端 LSDB 中的 LSA 类型和拓扑描述可能不同，可能导致 DR 状态异常、LSDB 不一致以及 SPF 计算异常。

😘多区域配置实验

区域内部路由器（Internal Router）：所有接口都属于同一个OSPF区域的路由器

  • 负责区域内部的路由计算，只维护所在区域的LSDB，通过Type 1 LSA描述自身链路状态。

区域边界路由器 ABR：同时连接两个或多个OSPF区域，并且其中一个必须是Area 0的路由器。

  • 连接不同OSPF区域，负责区域之间的路由传递，将一个区域的路由信息转换成Type 3 LSA发布到其他区域，同时隔离不同区域的LSDB

骨干路由器 Backbone Router：至少有一个接口属于Area 0的OSPF路由器，不一定是ABR。

  • 连接或属于Area 0的路由器，负责骨干区域的路由传输，是OSPF多区域通信的核心。

非骨干路由器：所有接口都不属于Area 0的路由器。

  • 不连接Area 0的路由器，只负责非骨干区域内部的路由转发，需要通过ABR访问其他区域。

ACL的问题

ACL只能匹配IP地址的某些位，不能匹配路由的掩码长度（Prefix Length）。如果想根据路由的掩码长度过滤，需要使用地址前缀列表（ip-prefix）。

比如：

1.1.1.1  /32 
1.1.1.0  /24  
1.1.0.0  /16   --过滤 
1.0.0.0  /8  
acl  2000     
rule   5  permit    source   1.1.0.0   0.0.255.255 
这样子acl就能匹配到前面三个

解决办法：地址前缀列表

地址前缀列表

地址前缀使用模板

ip ip-prefix 名称 index 序号 {permit|deny} 网络地址 掩码长度 [greater-equal 最小掩码] [less-equal 最大掩码]

网络地址 掩码长度：作为地址匹配的前缀。

[greater-equal n] [less-equal m]：n≤x≤m，x为指定的精准匹配的掩码范围。

例如：

ip ip-prefix lxf index10 permit1.1.0.016 greater-equal24 less-equal32

含义：

  • 名称：lxf
  • 序号：10
  • 动作：permit
  • 基准网络：1.1.0.0/16
  • 匹配掩码范围：/24 ~ /32

虚链路是 OSPF 解决不规则区域组网问题的一种机制，作用是逻辑上把非骨干区域连接到 Area 0（骨干区域），保证 OSPF 满足：

所有非骨干区域必须直接连接 Area 0。

虚链路必须配置在：

两个 ABR 上

而且：

  • 两个 ABR 必须存在一个共同的非骨干区域
  • 使用对方的 Router ID 建立

虚链路通过中间区域建立逻辑骨干连接，因此依赖中间区域的稳定性。如果中间区域出现故障或不稳定，会影响虚链路状态以及区域间路由传递，所以虚链路通常作为临时解决方案使用。

解决办法：BFD 双向检测机制

简介

双向转发检测BFD（Bidirectional Forwarding Detection）是一种全网统一的检测机制，用于快速检测、监控网络中链路或者IP路由的转发连通状况。

BFD提供了一个通用的标准化的介质无关和协议无关的快速故障检测机制。具有以下优点：

  • 对相邻转发引擎之间的通道提供轻负荷、快速故障检测。这些故障包括接口、数据链路，甚至有可能是转发引擎本身。
  • 用单一的机制对任何介质、任何协议层进行实时检测。

使用UDP端口号

默认是：3784 单跳BFD，4784是多跳BFD

原理

BFD在两台网络设备上建立会话，用来检测网络设备间的双向转发路径，为上层应用服务。BFD本身并没有邻居发现机制，而是靠被服务的上层应用通知其邻居信息以建立会话。会话建立后会周期性地快速发送BFD报文，如果在检测时间内没有收到BFD报文则认为该双向转发路径发生了故障，通知被服务的上层应用进行相应的处理。下面以OSPF与BFD联动为例，简单介绍会话工作流程。

BFD与静态路由联动

与动态路由协议不同，静态路由自身没有检测机制，当网络发生故障的时候，需要管理员介入。BFD与静态路由联动特性可为公网静态路由绑定BFD会话，利用BFD会话来检测静态路由所在链路的状态。

情况一：

R1 ---------------- R2
   二层链路

链路断了之后，路由器的接口都down，此时路由表会检测不到下一跳，路由条目消失

情况二：

R1 ---- SW ---- R2

SW被shutdown之后，但是接口还是绿的，此时路由条器会以为正常，导致静态路由条目依旧存在。
