链路聚合

⚽链路聚合

小知识：
带宽（Bandwidth）：

带宽是链路在单位时间内可承载的数据传输能力上限，单位通常为 bit/s（bps、Mbps、Gbps）。

要点：

  • 是容量上限，不是实际传输量
  • 由接口速率、链路介质、设备能力共同决定
  • 类似“高速公路车道数”，车道越多，理论通过能力越大

吞吐量（Throughput）

吞吐量是实际传输成功的数据速率。

关系：

  • 吞吐量 ≤ 带宽
  • 受以下因素影响：
    • 拥塞
    • 丢包重传
    • 协议开销（TCP/IP 头、ACK）
    • 设备处理能力

例：

  • 带宽 1Gbps
  • 实际测速 600Mbps → 这是吞吐量

😵网络可靠性

概述

1）网络可靠性

设备、链路备份，网关备份。

可以从单板、链路、设备三个模块讲。

2）单板可靠性

单板可靠性 = 硬件稳定性 + 故障隔离能力 + 故障恢复能力

3）设备、链路可靠性

即之前学的STP、VRRP

为保证设备间链路可靠性,在设备间部署多条物理线路,为防止环路STP只保留一条链
路转发流量,其余链路成为备份链路。

😽背景

1）早期网络结构：

  • 接入 → 汇聚：一条物理链路
  • 链路速率固定（如 1Gbps）

当终端增多：

  • 流量汇聚到一条链路
  • 出现拥塞、丢包、延迟上升

👉 瓶颈集中在上行链路

升级设备、链路成本高

2）链路可靠性

  • 只有一条上行链路
  • 一旦断开 → 网络中断

👉 典型单点故障

前期解决方案：STP（双链路接入，一条阻塞一条通行）

问题：

  • 备用链路不工作（浪费带宽）
  • 收敛慢（秒级甚至更慢）

😆基本原理

以太网链路聚合Eth-Trunk：简称链路聚合,通过将多个物理接口捆绑成为一个逻辑接
口,可以在不进行硬件升级的条件下,达到增加链路带宽的目的。

🥰链路聚合的相关概念

1、聚合组（Link Aggregation Group，LAG）

将若干条物理链路捆绑在一起后，形成的一条逻辑链路，每个聚合组唯一对应一个逻辑接口，这个逻辑接口称为：Eth-Trunk 接口

2、成员接口 / 成员链路

组成 Eth-Trunk 接口的各个物理接口，称为成员接口；

这些成员接口所对应的物理链路，称为成员链路。

3、活动接口 / 活动链路

活动接口也叫选中接口（Selected），指当前参与数据转发的成员接口；

其对应的链路称为活动链路（Active link）。

（聚合组中不是所有的成员链路都参与数据转发）

4、非活动接口 / 非活动链路

非活动接口也叫非选中接口（Unselected），指当前不参与数据转发的成员接口；

其对应的链路称为非活动链路（Inactive link）。

🤑聚合模式

手工模式（默认）

手工模式:Eth-Trunk的建立、成员接口的加入均由手动配置，双方系统之间不使用LACP进行协商。

正常情况下所有链路都是活动链路，该模式下所有活动链路都参与数据的转发，平均分担流量,如果某条活动链路故障,
链路聚合组自动在剩余的活动链路中平均分担流量。

什么时候使用手工模式？

当聚合的两端设备中存在一个不支持LACP协议时，可以使用手工模式。

当聚合的两端设备的厂商不一样时，使用手工模式。

在手工模式下：

成员链路 = 活动链路

只要接口：

  • 物理状态 Up
  • 成功加入 Eth-Trunk

👉 就会参与转发（Active）

手工模式下，设备间没有报文交互，因此只能通过管理员人工确认

缺陷

1）聚合组之间的接口不对应（数据传输问题）

2）聚合链路连接到第三个设备（信息泄露）

😝LACP模式

在手工模式下，所有接口和链路都是活动状态，但是当流量不大时，原本仅需2条链路即可传输，手工模式下不能改变。

LACP协议可以通过算法来控制。

会从所有成员接口中：

  • 选出 Active链路（参与转发）
  • 其余变为 Inactive（备用）

🫶🏼LACP选举主设备（主动端）和活动接口（优先级越小越好）

首先，先选举主设备（主动端），当使用LACP时只会通过选举一端的设备来决定哪个接口active，否则两端设备一起决定活动链路的话会产生冲突。

主设备（主动端）→先看系统优先级，系统优先级越小，就越容易被选举出来→若系统优先级相同，则对比MAC地址，同样也是越小越容易被选举。

接着选举出来的主动端会来选举活动接口（成员接口数目大于最大活动接口数）

活动接口→先看接口优先级，同样也是越小越好→当接口优先级相同，则对比接口编号。

活动接口对应链路也成为活动链路，其余的则做备用（非活动链路、非活动接口）。

交换机只会从活动接口中发送、接收报文。

当活动链路因故障退出后，备用链路会顶替其转发业务；原链路恢复正常后，会重新参与 LACP 选举，若其优先级更高，则可能重新成为活动链路。该过程需要经过状态恢复与协议收敛，因此不会瞬间切换，可在一定程度上避免链路频繁震荡。

😪负载分担

🧔🏼‍♂️基于包的负载分担

优点

将数据分成一个个包，根据哈希算法负载分担到各个链路上。

同一个流的数据包可以走不同的链路，使链路减少闲置，利用率增大。

缺点

乱序

不同链路的延迟不同，数据包到达设备的时间不同，导致乱序。

乱序导致误判丢包，数据重传。

数据流（flow）是指一组具有相同特征的数据包集合，这些数据包属于同一次通信

五元组

源IP（SIP）
目的IP（DIP）
源端口（Sport）
目的端口（Dport）
协议（TCP/UDP）

💟基于流的负载分担

计算机数据流会选择一条链路作为其流的传输，属于同一条流的数据包都从该链路转发。

优点

同一流 → 固定一条链路 → 延迟一致 → 顺序稳定

👉 TCP性能稳定，不会误判丢包

缺点

负载不均衡，有些链路会空闲。

知识总结：

  • 手工模式（manual）
    • 不依赖协议
    • 所有成员链路默认参与转发

  • LACP模式（lacp-static）

    • 支持链路优先级、最大活动链路数控制

周末实验

配置思路：
总公司：SW4、SW5、SW6、SW7，连接终端用access接口，连接聚合交换机用链路聚合接口trunk，其中两个聚合交换机之间用lacp模式，其他用手工模式。聚合交换机SW2和SW3连接DHCP服务器用trunk，并且只允许vlan66。

NAT设备用acl2000

网关为SW2和SW3，因为DHCP报文需要和网关交流，所以在DHCP服务器、SW2、SW3需要配置

instance 1 valn 10 20 insrance 2 vlan 30 40 instance 3 vlan 66（否则DHCP服务器和SW2、SW3之间的链路，vlan66的报文会属于实例0，且之间是阻断的。）

分公司：接入层交换机连接终端和聚合交换机都用aceess。

出现的问题：
1）配置总公司的时候没有将每个设备都配置stp，导致最后终端接收不了参数。

2）忘记配置dot1q termination vid xx ，分公司的终端无法接受参数

3）分公司的接入层交换机和聚合交换机之间用了trunk，导致参数无法到达终端。

instance 1 vlan 10 20 50

AR5为DHCP服务器，配置vlan50的地址，还有去往SW11的默认路

😠链路聚合的M:N模式

M:N 模式表示链路聚合组中：

M:N=活动链路数:备份链路数

也就是说，在一个 Eth-Trunk 聚合组中，不一定所有成员链路都参与转发，可以只让部分链路转发，剩余链路作为备用链路。

聚合链路中“分包”和“哈希转发”的关系

1. 数据确实会被拆成很多包

例如发送一个文件：

完整文件
   ↓
包1、包2、包3、包4、包5……

接收端会根据 TCP 序号把这些包重新排序、重组。

但是：

Eth-Trunk 不负责拼接数据，它只负责选择出接口转发。

2. 聚合链路不是“按包轮流发送”

错误理解：

包1 → GE0/0/1
包2 → GE0/0/2
包3 → GE0/0/3
包4 → GE0/0/1

这种方式虽然看起来平均，但容易导致乱序。

原因是不同链路的延迟、排队情况可能不同：

发送顺序：包1 → 包2 → 包3

到达顺序：包2 → 包3 → 包1

这样 TCP 需要重新排序，严重时还可能触发重传，影响传输效率。

3. 聚合链路通常是“按流分担”

正确理解：

同一条数据流的包，通常走同一条成员链路。

例如 PC1 访问服务器：

PC1 → Server 这条流

它被哈希到 GE0/0/2 后：

包1 → GE0/0/2
包2 → GE0/0/2
包3 → GE0/0/2
包4 → GE0/0/2

这样可以尽量保证同一条流内部的包按顺序到达。

5. 哈希算法根据什么判断

设备会根据报文中的字段计算哈希值，例如：

字段含义
源 IP谁发出的
目的 IP发给谁
源 MAC源设备 MAC
目的 MAC目的设备 MAC
源端口TCP/UDP 源端口
目的端口TCP/UDP 目的端口
VLAN ID所属 VLAN

在华为设备中常见方式：

SIP⊕DIP

即：

源 IP XOR 目的 IP

设备通过计算结果决定走哪一条成员链路。

6. 核心理解

链路聚合不是按“包”平均分配，
而是按“流”进行哈希分担。
